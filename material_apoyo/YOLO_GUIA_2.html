Manual de consulta técnica

Documentación de YOLO con Python

Fundamentos, métodos, parámetros y ejemplos para desarrollar aplicaciones de visión artificial.

01 · Introducción

¿Qué es YOLO?

YOLO (You Only Look Once) es una familia de modelos de visión artificial que permite detectar objetos en imágenes y videos.

Su función principal es identificar qué objetos aparecen en una imagen y determinar en qué posición se encuentran.

¿Qué información proporciona?

  • Nombre o clase del objeto.
  • Ubicación del objeto mediante un rectángulo.
  • Confianza de la predicción.
  • Coordenadas de cada detección.

Ejemplo de detección

Si presentamos una imagen que contiene una botella y un martillo, el modelo podría devolver: 

Objeto: botella
Confianza: 0.94
Coordenadas: [120, 80, 250, 340]

Objeto: martillo
Confianza: 0.89
Coordenadas: [300, 100, 480, 390]
La confianza es una estimación del modelo sobre su predicción. No debe interpretarse como una garantía de que la detección sea correcta.
02 · Tareas

¿Qué puede hacer YOLO?

Detección de objetos (Detect)

Identifica objetos y dibuja rectángulos delimitadores alrededor de ellos. Es la tarea que utilizaremos en nuestros laboratorios.

Segmentación (Segment)

Identifica los objetos y determina los píxeles que pertenecen a cada uno mediante máscaras.

Clasificación (Classify)

Asigna una categoría a una imagen completa, sin localizar individualmente los objetos.

Estimación de pose (Pose)

Identifica puntos clave del cuerpo u otros elementos para estimar posiciones y movimientos.

Detección de cajas orientadas (OBB)

Localiza objetos utilizando rectángulos que pueden tener diferentes ángulos de rotación.

TareaResultadoEjemplo
DetectRectángulosReconocer herramientas
SegmentMáscarasSeparar piezas
ClassifyClasesClasificar fotografías
PosePuntos claveAnalizar movimientos
OBBRectángulos rotadosIdentificar piezas inclinadas
Los modelos deben corresponder a la tarea que se desea realizar. Un modelo de detección no produce automáticamente máscaras de segmentación.

04 · Modelos

Tipos de modelos y archivos

Los modelos de Ultralytics pueden cargarse desde diferentes archivos según el propósito del proyecto.

ArchivoFunción
.ptPesos de un modelo de PyTorch.
.yamlConfiguración de la arquitectura.
.onnxModelo exportado para otros entornos.
.engineMotor optimizado de TensorRT.
.tfliteFormato TensorFlow Lite, según compatibilidad.

Variantes de modelos

En una familia de modelos como YOLO26 existen diferentes tamaños para equilibrar velocidad, recursos y precisión.

VarianteCaracterística general
n (Nano)Más ligera y rápida.
s (Small)Ligera con mayor capacidad.
m (Medium)Equilibrio entre tamaño y capacidad.
l (Large)Mayor capacidad computacional.
x (Extra Large)Modelo de mayor tamaño.

Cargar un modelo preentrenado

model = YOLO("yolo26n.pt")

Cargar un modelo personalizado

model = YOLO("best.pt")

Crear un modelo desde su arquitectura

model = YOLO("yolo26n.yaml")
Para aprender a entrenar objetos propios, normalmente se recomienda comenzar desde pesos preentrenados (.pt), en lugar de inicializar todos los pesos aleatoriamente.
05 · Datos

Conjuntos de datos (Dataset)

Un dataset es un conjunto organizado de imágenes y etiquetas que permite entrenar y evaluar un modelo.

Distribución de imágenes

GrupoUso
TrainEnseñar al modelo.
ValidationMedir su comportamiento durante el desarrollo.
TestEvaluar el modelo con datos reservados.

Ejemplo de estructura

dataset/
│
├── data.yaml
│
├── train/
│   ├── images/
│   └── labels/
│
├── valid/
│   ├── images/
│   └── labels/
│
└── test/
    ├── images/
    └── labels/

Formato de las etiquetas

En detección, cada imagen puede tener un archivo TXT asociado. Cada línea representa un objeto. 

0 0.500 0.450 0.300 0.400
1 0.700 0.600 0.200 0.250
CampoDescripción
0Identificador de clase.
0.500Centro horizontal normalizado.
0.450Centro vertical normalizado.
0.300Ancho normalizado.
0.400Alto normalizado.

Archivo data.yaml

path: ./dataset

train: train/images
val: valid/images
test: test/images

names:
  0: botella
  1: lata
  2: martillo

Este archivo conecta las imágenes del dataset con los nombres de las clases.

Recomendaciones para etiquetar

  • Marcar completamente cada objeto.
  • No incluir demasiado fondo en los rectángulos.
  • Mantener las clases consistentes.
  • Evitar imágenes borrosas o etiquetas incorrectas.
  • Incluir diferentes posiciones y condiciones.
  • Reservar imágenes independientes para la evaluación.
06 · Entrenamiento

Método train()

Permite entrenar un modelo utilizando un conjunto de datos y diferentes parámetros de configuración.

Sintaxis general

resultados = model.train(

Los valores de estos parámetros son configurables. No todos son necesarios en un mismo entrenamiento. Conviene experimentar de forma controlada y observar los resultados.

Ejemplo de entrenamiento avanzado

from ultralytics import YOLO

model = YOLO("yolo26n.pt")

model.train(
    data="dataset/data.yaml",
    epochs=100,
    imgsz=640,
    batch=8,
    patience=25,
    optimizer="auto",
    degrees=10,
    fliplr=0.5,
    mosaic=1.0,
    name="experimento_01"
)

¿Qué es una época?

Una época representa un recorrido completo por el conjunto de entrenamiento. Por ejemplo, con 100 épocas el modelo procesará el conjunto de entrenamiento hasta 100 veces, salvo que se detenga anticipadamente.

¿Qué es batch?

Es la cantidad de imágenes que se procesan en cada lote. Un batch mayor puede requerir más memoria.

¿Qué es imgsz?

Es el tamaño de entrada utilizado para procesar las imágenes. Una resolución mayor puede ayudar con objetos pequeños, pero requiere más recursos computacionales.

07 · Validación

Método val()

Permite evaluar el modelo con un conjunto de validación para medir su capacidad de reconocer los objetos. 

from ultralytics import YOLO

model = YOLO("best.pt")

metricas = model.val()

print("mAP50:", metricas.box.map50)
print("mAP50-95:", metricas.box.map)
print("Precision:", metricas.box.mp)
print("Recall:", metricas.box.mr)

Principales métricas

MétricaInterpretación
Precision Proporción de detecciones positivas que fueron correctas.
Recall Proporción de objetos reales que fueron detectados.
mAP50 Precisión media con IoU de 0.50.
mAP50-95 Promedio de precisión media con IoU entre 0.50 y 0.95.

Ejemplo de interpretación

Un modelo puede tener una precisión elevada, pero un recall bajo. Esto significa que las detecciones que realiza suelen ser correctas, pero puede estar dejando pasar muchos objetos.

No existe un valor universal que garantice un buen modelo. Las métricas deben interpretarse según el problema y las condiciones reales de funcionamiento.
08 · Predicción

Método predict()

Permite utilizar un modelo entrenado para detectar objetos en imágenes, videos, carpetas o cámaras.

Detectar en una imagen

from ultralytics import YOLO

model = YOLO("best.pt")

results = model.predict(
    source="imagen.jpg",
    conf=0.50,
    save=True
)

Detectar en una carpeta

results = model.predict(
    source="imagenes/",
    conf=0.40,
    save=True
)

Detectar en un video

results = model.predict(
    source="video.mp4",
    conf=0.50,
    save=True
)

Detectar con cámara web

results = model.predict(
    source=0,
    conf=0.50,
    show=True
)

Parámetros principales

ArgumentoDescripción
sourceOrigen de la imagen o video.
confConfianza mínima de detección.
iouUmbral IoU para supresión de cajas duplicadas.
imgszResolución de entrada.
showMostrar resultados.
saveGuardar imágenes o videos procesados.
save_txtGuardar detecciones en archivos TXT.
save_confIncluir confianza en los TXT guardados.
classesFiltrar por identificadores de clase.
max_detMáximo de detecciones por imagen.
deviceDispositivo de inferencia.
streamProcesar resultados como generador.
verboseMostrar información detallada.

¿Qué significa conf?

El argumento conf establece la confianza mínima necesaria para mostrar una detección. 

# Mostrar detecciones con confianza >= 0.25
model.predict(source="imagen.jpg", conf=0.25)

# Mostrar detecciones con confianza >= 0.70
model.predict(source="imagen.jpg", conf=0.70)
Aumentar conf puede eliminar detecciones incorrectas, pero también puede hacer que desaparezcan objetos que sí existen.

¿Qué significa IoU?

IoU (Intersection over Union) mide el grado de superposición entre dos rectángulos.

Se utiliza en la evaluación de detecciones y en la eliminación de cajas duplicadas mediante NMS. 

model.predict(
    source="imagen.jpg",
    conf=0.40,
    iou=0.50
)
09 · Resultados

Interpretar los resultados de predict()

El método predict() devuelve una lista de objetos Results. Cada elemento representa el resultado correspondiente a una imagen o fotograma procesado.

Recorrer las detecciones

results = model.predict("imagen.jpg")

for resultado in results:

    for caja in resultado.boxes:

        clase = int(caja.cls[0])
        confianza = float(caja.conf[0])

        nombre = resultado.names[clase]

        print(nombre, confianza)

Información de cada caja

PropiedadDescripción
boxesContenedor de las detecciones.
boxes.clsIdentificador de clase.
boxes.confConfianza de cada detección.
boxes.xyxyCoordenadas x1, y1, x2, y2.
boxes.xywhCentro x, centro y, ancho y alto.
namesDiccionario de nombres de clases.
orig_shapeDimensiones originales de la imagen.

Obtener coordenadas

for resultado in results:

    for caja in resultado.boxes:

        x1, y1, x2, y2 = caja.xyxy[0].tolist()

        print("X inicial:", x1)
        print("Y inicial:", y1)
        print("X final:", x2)
        print("Y final:", y2)

Obtener la imagen con las detecciones

for resultado in results:

    imagen = resultado.plot()

El método plot() devuelve una imagen con los rectángulos, etiquetas y valores de confianza dibujados.

Filtrar por clase

# Detectar únicamente las clases 0 y 2

results = model.predict(
    source="imagen.jpg",
    classes=[0, 2]
)
10 · Otros métodos

Métodos adicionales

track()

Realiza seguimiento de objetos a través de diferentes fotogramas de un video. 

results = model.track(
    source=0,
    show=True,
    tracker="bytetrack.yaml"
)

A diferencia de predict(), el seguimiento intenta conservar un identificador para cada objeto a través del tiempo.

export()

Convierte el modelo a otro formato para facilitar su utilización en diferentes plataformas. 

model.export(format="onnx")

Algunos formatos disponibles:

  • onnx
  • openvino
  • engine
  • torchscript
  • tflite
  • coreml

benchmark()

Permite comparar el rendimiento de diferentes formatos de exportación. 

from ultralytics.utils.benchmarks import benchmark

benchmark(
    model="best.pt",
    data="dataset/data.yaml",
    imgsz=640
)

resume()

El entrenamiento puede reanudarse utilizando el último punto de control compatible. 

model = YOLO("last.pt")

model.train(resume=True)
Para reanudar correctamente un entrenamiento interrumpido, se utiliza el checkpoint last.pt, no best.pt.

12 · Problemas frecuentes

Errores y posibles soluciones

YOLO no encuentra el archivo data.yaml

Verificar la ruta especificada en el argumento data y comprobar que el archivo exista.

El modelo no reconoce mis objetos

Verificar las etiquetas, aumentar la variedad de imágenes y comprobar que las clases estén correctamente configuradas.

El entrenamiento consume demasiada memoria

Reducir batch, utilizar una variante más ligera o disminuir imgsz.

El modelo confunde dos objetos

Agregar imágenes variadas de ambas clases y verificar que las etiquetas sean correctas.

El modelo detecta objetos que no existen

Revisar la calidad del dataset y experimentar con el valor de conf. También es importante probar imágenes de escenarios diferentes.

La cámara web no funciona

Verificar el índice de cámara, los permisos del sistema y que otra aplicación no esté utilizando el dispositivo.

No aparece la GPU

Comprobar la instalación de PyTorch, los controladores y la compatibilidad de CUDA con el entorno instalado.

13 · Recomendaciones

Buenas prácticas

  • Utilizar imágenes de buena calidad.
  • Etiquetar correctamente todos los objetos relevantes.
  • Evitar clases con nombres o identificadores inconsistentes.
  • Separar adecuadamente train, valid y test.
  • Conservar los mejores pesos del entrenamiento.
  • Evaluar con imágenes que el modelo no haya visto.
  • Modificar un parámetro a la vez para comparar resultados.
  • Documentar los cambios entre entrenamientos.

Una consideración importante

Un modelo personalizado no aprende automáticamente nuevas clases cuando se le presenta un objeto desconocido.

Para reconocer nuevas categorías se debe preparar un conjunto de imágenes que las represente, etiquetarlas y entrenar o ajustar el modelo.

El modelo best.pt puede integrarse posteriormente en sistemas de inspección, clasificación de piezas, bandas transportadoras, robótica y aplicaciones de visión artificial.
